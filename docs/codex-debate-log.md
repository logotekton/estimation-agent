## 사전 준비 — Claude 측 독립 재검토 논점 (토론 전 자체 발굴)

토론에 공정하게 임하기 위해 Codex 리뷰를 보기 전에 스스로 발굴한 약점 목록:

- **C-1. 벡터 PDF의 SHX 텍스트 아웃라인화**: AutoCAD가 SHX 폰트 텍스트를 PDF로 플롯하면
  텍스트 엔티티가 아니라 기하(선분)로 변환된다. "벡터 PDF = 1급 입력, 결정론 텍스트 파싱"
  가정이 한국 실무(SHX 한글 폰트 광범위 사용)에서 붕괴할 수 있음. 계획서 §3의 공백.
- **C-2. N=50 실무 도면 소싱의 선후관계 모순**: DWG 스파이크는 0단계 게이트인데,
  실무 DWG 50장은 파일럿 파트너 없이는 구하기 어려움(공공 입찰 첨부는 대부분 PDF).
  병렬 트랙에 "소싱"이라고만 적혀 있고 소싱 채널이 미정의 — 게이트가 병렬 트랙에 의존.
- **C-3. 폰트/인코딩 리스크**: LibreDWG 엔티티 보존율만 보고 있는데, 한국 CAD 환경의
  SHX 미동봉·CP949 인코딩·커스텀 폰트로 인한 텍스트 손실은 별도 축의 실패 모드.
- **C-4. 용도 c(내역 검증)의 숨은 모듈**: 발주 내역서(엑셀/HWP)를 파싱해서 시스템 BOQ와
  라인 매칭하는 모듈이 파이프라인에 없음. 품명·규격 텍스트 매칭은 자체로 어려운 문제.
  디스크레펀시 리포트가 "단독 상품"이 되려면 이 모듈이 필수인데 §11 후순위 목록에도 없음.
- **C-5. 리비전 carry-forward의 좌표계 문제**: 리비전 간 원점 이동·시트 재배치 시
  사람이 확정한 벽 경계(좌표 기반)의 이월이 깨짐. 스키마에 "정책 포함"이라고만 되어 있음.
- **C-6. 뷰어 후보 3의 래스터 배경도 렌더러 필요**: "원본은 래스터 스냅샷"이라지만
  DWG→래스터 렌더링 자체가 충실도 문제를 되부름(LibreDWG dwg2SVG 품질 한계).
- **C-7. 엔지니어 채용 리드타임**: 적산 전문가만 "즉시 착수"로 명시, CAD 파싱 엔지니어
  채용 리드타임은 언급 없음. 5~6개월 추정의 암묵 전제.
- **C-8. GT 2건 2인 독립 산출의 통계력**: inter-annotator 편차 추정에 n=2는 빈약.
  (계획서도 "최소"라고는 명시)

## 라운드 1 — Codex 독립 리뷰 (웹 검색 근거 포함, 전문: codex-debate/01-codex-review.md)

**결론**: "진행 가능하지만 엄격한 0단계 게이트 후 조건부 진행이어야 함."

**치명적 결함 3건**:
- **X-1. LibreDWG 과신**: 공식 문서상 beta 성격, R2010+ 일부 엔티티 skip,
  PROXY_ENTITY 미지원, TABLE 제약. 실무 견적에는 "열 수 있음"이 아니라
  "치수·MTEXT·TABLE·BLOCK/XREF·SHX 한글·proxy가 조용히 누락되지 않음"이 필요.
  현 스파이크에 엔티티별 recall/precision, silent-drop 허용치, 한글 무결성 기준 없음.
- **X-2. GPL 격리 판단 불완전**: SaaS는 문제 작으나 온프레미스 동봉 배포는
  "별도 프로세스" 형식만으로 충분하지 않을 수 있음(FSF arm's-length 요건).
  온프레미스가 중요 세그먼트면 ODA(연 $7,500~)를 초기 원가 구조에 반영해야.
- **X-3. 평가 통계 미성립**: NI 마진·분석 단위·검정 방법·표본수 사전 정의 부재.
  GT 10건은 과소(10건 무결함이어도 95% 상한 ~26%). 라인 수백 개도 프로젝트·도면·
  검토자에 묶인 군집 자료 — 독립 표본 취급 불가. paired binary는 McNemar류 필요.

**중요 결함 3건**:
- **X-4. 룰 엔진 스코프 과대 + 철근 ±10% 과감**: 정본이 하나로 안 합쳐짐(특기시방·
  유의서·관행·공제 충돌). 2a에서 철근은 "정미량 초안/고위험 플래그"로 강등 권고.
- **X-5. 벽식 UX 지표 부족**: "개입 1회당 시간"보다 층·동·타입당 개입 수,
  carry-forward 재검증 시간, carry-forward 오류율이 핵심.
- **X-6. 용도 c 시장성 가설 수준**: 구매 이유는 물량 오류 발견 자체가 아니라
  입찰 리스크 회피·클레임 근거·감수비 절감 같은 경제 사건. 세그먼트별 ROI 검증 선행 필요.

**사소 3건**:
- **X-7**: HANDOFF "5라운드" vs 계획서 "4라운드" 표기 불일치.
- **X-8**: 0단계 종료 조건에 통과/실패 수치 기준 부재.
- **X-9**: 뷰어 후보 3의 래스터 배경↔벡터 오버레이 좌표 정합 오차 허용치 부재.

## 라운드 2 — Claude 응답 (전문: codex-debate/02-claude.md)

- **X-1 전면 수용 + 구체화**: 엔티티군별 recall 분리 집계 / silent-drop 0 허용(치수·
  텍스트·블록참조) / 한글 무결성 별도 축(SHX·CP949 시나리오 의도 포함) /

  과했음을 인정. 절충: 온프레미스 GA 전 법무 검토 게이트 + ODA $7.5k/yr 온프레미스
  티어 원가 사전 반영 + SaaS는 LibreDWG 유지.
- **X-3 대체 수용 + 스코프 반박**: FDA급 설계는 파일럿에 과잉(규제 아닌 내부 게이트).
  수정안: 항목 풀 단위 + 프로젝트 클러스터 robust CI / δ는 GT 2인 편차에서 사전 도출 /
  McNemar·GEE 명기 / 검정력 게이트(통과 전 프로젝트 단위 NI 선언 불가) 격상.
- **X-4 수용 + 부분 반박**: 철근 2a 강등(정미량 초안+고위험 플래그) 수용. 단 "정본이
  안 합쳐진다"는 기존 오버라이드 레이어 구조가 이미 수용한 내용 — 프로젝트(특기시방)
  계층 추가로 보완.
- **X-5 전면 수용**: 벽식 지표 3종 추가.
- **X-6 수용 + C-4 보강**: 내역서 파싱·라인 매칭 모듈의 부재를 명시적 후순위로,
  파일럿 용도 c는 수동 대조 반자동으로 시작. 구매 경제 인터뷰를 병렬 트랙에 추가.
- **X-7~9 전부 수용**.
- **추가 판정 요청**: C-2(N=50 소싱 모순), C-5(리비전 좌표계), C-6(뷰어 후보 3 순환
  의존), C-7(엔지니어 채용 리드타임), C-8(GT n=2 통계력).

## 라운드 3 — Codex 판정 (전문: codex-debate/03-codex.md)

- **X-1 승복** + C-1 승복. PDF는 "텍스트 추출 가능 벡터 PDF"와 "기하화된 벡터 PDF"로
  등급 분리 필요 (DXF와 같은 1급으로 묶지 말 것).
- **X-2 조건부 승복**: 방어 논리는 인정, 단 "mere aggregation 방어 가능"도 법무 검토
  전 단정 금지. 법무 검토 시점은 온프레미스 GA 전이 아니라 **유료 파일럿 계약 전**.
- **X-3 조건부**: 수정안 충분하나 파일럿 설계 변경 필요 — 같은 도면 paired
  (수작업 vs 시스템 보조) + 독립 adjudicator의 blind/masked 판정.
  "검토 완료 BOQ 사후 GT 축적"은 시스템 산출물이 GT를 오염시킬 수 있음.
- **X-4 조건부 승복**: 원 지적은 레이어 부재가 아니라 **precedence·충돌해결·룰 검증
  체계 부재**. precedence 명시 + 룰 테스트 + 변경 이력 + 승인권자 명시 시 이견 없음.
- **X-5, X-6 승복**. 용도 c 단독 상품화 전에는 내역서 매칭 모듈이 후순위 목록에서
  빠져나와야 함.
- **C-2 승복**: 게이트 2단 분리 — 1차 smoke N=10~20(NDA 샘플·협력사·공개 PDF 원본
  요청), full gate N=50 (2a 착수 전). ZWCAD/CADian 의도 포함.
- **C-5 승복**: 스키마 v0에 기하 앵커링(그리드 교차점·축선·블록 기반 상대좌표,
  affine transform) 필수.
- **C-6 승복**: 결합 매트릭스에 명시. 렌더 실패 시 대안: ODA·headless CAD·고객 제공
  PDF·사전 플롯 워크플로우.
- **C-7 승복**: CAD 파싱 엔지니어도 즉시 착수 트리거로.
- **C-8 승복**: 1차 웨이브 최소 3건, 가능하면 전건 2인 산출. 비용 부담 시 공종/부재 풀
  층화 샘플링으로 2인 adjudication 범위 확대.

**남은 이견 3건**: X-2 단정 금지 / X-3 paired 프로토콜·독립 판정 / X-4 precedence 체계.

## 라운드 7 — 역방향 점검: 토론 자체의 과잉 수정 검증 (전문: codex-debate/12-claude.md, 13-codex.md)

Claude 제기: 결함 추가 방향으로만 토론했다 — 토론 자체가 계획을 과잉 수정했는가?
(게이트 마비 / 0단계 과적재 / 방어 장치 비용 비대칭 / 문서의 리스크 백과사전화)

**Codex 판정 — "일부 과잉 수정 있음. 방어 장치 자체는 과잉이 아니나 게이트의
blocking level이 과잉":**
- 게이트를 4분류로 재편: **착수 차단**(0A/0B smoke·자본 대략 확인) /
  **판매·확장 차단**(full N=50·온프렘 법무·상업 게이트) / **주장 차단**(검정력·NI —
  개발·판매는 안 막음) / **전략 리뷰**(해자 검증 — 아무것도 안 막음).
- 최대 수정 지점: "full N=50 = 2a 착수 전"은 과함 → **2a 개발은 smoke 통과 후 착수**,
  full N=50은 "DWG 의존 유료 파일럿/시장 약속 전"으로 하향.
- 0단계 분할: 0A(2주, N=5~10 경로 결정) → 0B(4~6주, N=10~20 정량 리포트) →
  full N=50은 2a와 병행 수집. 스파이크 산출물 = 버리는 검증 하네스 + 보고서.
- 비용 대칭성: 3-arm paired·masked adjudication은 gold GT+샘플 한정 / 골든 테스트는
  핵심 룰 5~10개 스냅샷부터 / bus factor는 SOP·playbook 먼저 / 채택 KPI는 수동
  체크리스트 / 검정력·cluster CI는 분석 노트북으로.
- 유지해야 할 것(문서 장식이 아닌 것): silent-drop 0건·한글 축·PDF 등급 분리·
  엑셀 퍼스트·UI 금지 목록·상업 게이트.
- 문서 앞에 "실행 spine 1페이지" 필요.

→ Claude 전면 수용, 계획서에 반영 (실행 스파인 신설·게이트 4분류 표·로드맵 0단계
재구성·비용 대칭성 조정).

다음 행동으로 읽히고, 게이트 4분류가 착수 차단 문제를 해소했다. full N=50이 2a 착수를
