**과제 1 — 반영 충실성**

대부분 정확히 반영됐습니다. 특히 DWG/PDF 스파이크, GPL 문구, 평가 통계, gold/silver GT, 철근 강등, 룰팩 거버넌스, 벽식 지표, 내역서 매칭 후순위화, C-2~C-8은 합의 취지대로 들어갔습니다.

다만 아래는 수정 필요합니다.

1. **GPL 문구가 §9에서 다시 약화됨.**  
   [§3 입력 계층](C:/Logotekton/Estimate-Agent/docs/estimation-automation-plan.md:95)은 “법적 결론은 법무 검토로만 확정”이라고 정확히 고쳤습니다. 그런데 [§9](C:/Logotekton/Estimate-Agent/docs/estimation-automation-plan.md:196)은 여전히 “프로세스 격리로 라이선스 리스크 사전 차단”이라고 씁니다. 이건 X-2 합의를 되돌리는 표현입니다.  
   수정: “§3의 arm’s-length 방어 논리와 법무 게이트로 관리” 정도로 바꿔야 합니다.

2. **GT 10건 문구가 X-3과 충돌합니다.**  
   [성공지표 표](C:/Logotekton/Estimate-Agent/docs/estimation-automation-plan.md:14)는 “프로젝트 단위 통과 판정은 GT 10건+ 축적 후”라고 남아 있습니다. 그러나 [검정력 게이트](C:/Logotekton/Estimate-Agent/docs/estimation-automation-plan.md:26)는 “검정력 산정 통과 전 NI 선언 불가”입니다.  
   수정: “GT 10건+는 최소 축적 기준일 뿐, 통과 판정은 검정력 게이트 충족 후”라고 명시해야 합니다.

3. **‘무비용’ 표현이 과합니다.**  
   [기준선 확보](C:/Logotekton/Estimate-Agent/docs/estimation-automation-plan.md:31)에 “무비용”이라고 되어 있는데, 3-arm paired와 masked adjudication은 운영비가 듭니다. “기존 GT 웨이브에 얹어 추가비용을 최소화”가 맞습니다.

4. **용도 c 단독상품 문구가 아직 강합니다.**  
   [2차 세그먼트](C:/Logotekton/Estimate-Agent/docs/estimation-automation-plan.md:77)는 “디스크레펀시 리포트 단독으로 앵커”라고 하지만, 바로 뒤 [구매 경제 검증](C:/Logotekton/Estimate-Agent/docs/estimation-automation-plan.md:79)은 내역서 파싱·BOQ 라인 매칭 없이는 단독 상품화가 어렵다고 인정합니다.  
   수정: “잠재 앵커” 또는 “반자동 검증 워크플로우로 시작”으로 낮추는 게 맞습니다.

5. **도면 소싱 문구가 C-2 수정과 덜 맞습니다.**  
   [평가 체계](C:/Logotekton/Estimate-Agent/docs/estimation-automation-plan.md:187)는 “공공 발주 설계도서부터”라고 되어 있는데, C-2의 핵심은 공공 자료가 PDF 중심이라 DWG N=50 소싱에는 부족하다는 점이었습니다. [로드맵](C:/Logotekton/Estimate-Agent/docs/estimation-automation-plan.md:226)은 잘 고쳤으니, §8도 “공공 자료는 PDF/평가 보조, DWG는 NDA·협력사·파트너 채널”로 맞추는 게 좋습니다.

**과제 2 — 프리모템**

1. **채택 실패: 견적팀이 기존 엑셀 워크플로우를 떠나지 않음**  
   확률: **높음**.  
   죽는 경로: 시스템 정확도가 나쁘지 않아도, 견적팀은 도면 업로드 보안 부담, 엑셀/HWP 중심 산출물, 마감 임박 일정, 내부 결재 포맷 때문에 새 UI를 안 씁니다. “검토 UI가 본체”가 오히려 전환 비용이 됩니다.  
   예방: 첫 파일럿 산출물을 “웹앱 사용”이 아니라 “기존 엑셀 양식으로 근거 링크가 붙은 검토 리포트”로 정의하세요. 보안 문서, 온프렘/로컬 처리 옵션, 엑셀 export/import, 기존 내역 프로그램 연동을 채택 KPI에 넣어야 합니다.  
   계획 수정 필요: **예.** §12 출력 규격에 채택 마찰 KPI를 추가해야 합니다.

2. **경쟁 압축: 한국 룰팩이 해자가 아니라 기능으로 흡수됨**  
   확률: **중간~높음**.  
   Togal은 이미 AI takeoff, 비교, 클라우드 협업, “5x faster” 같은 메시지를 전면에 내세웁니다. Kreo도 agentic AI, cross-sheet 해석, Auto Measure, Excel Template Builder, 선호 학습을 제품화하고 있습니다.([Togal](https://www.togal.ai/), [Kreo](https://www.kreo.net/)) 이들이 한국 파트너나 로컬 룰팩을 붙이면 “한국 기준 + 근거 추적성”은 방어 가능한 해자가 아닐 수 있습니다.  
   예방: 단순 룰팩이 아니라 한국 내역 라인 매칭 데이터, 발주처별 precedence, 검증 로그, 고객별 오버라이드 이력에 대한 독점적 학습/계약 권리를 확보해야 합니다. 국내 적산 프로그램 업체와의 제휴/화이트라벨도 방어 옵션입니다.  
   계획 수정 필요: **예.** §2 경쟁 구도에 “해자 검증 게이트”를 추가해야 합니다.

3. **재무 실패: 파일럿 전환 전에 번레이트가 먼저 이김**  
   확률: **중간~높음**.  
   팀 4~6인, 상근 적산 전문가, GT 외주, 파일럿 지원, ODA 가능성까지 포함하면 5~6개월이 아니라 18개월 생존 자본이 필요합니다. 건당 과금은 초기에는 매출 인식이 늦고, 파일럿은 할인/무상일 가능성이 큽니다.  
   예방: 0단계 종료 전에 필요한 자본, 월 번레이트, 유료 전환 건수, 목표 프로젝트 단가, gross margin, GT 비용 상한을 숫자로 박아야 합니다. “파일럿 3건 중 1건 유료 전환” 같은 상업 게이트가 필요합니다.  
   계획 수정 필요: **예.** 재무 게이트가 현재 문서에 없습니다.

4. **키맨 병목: 상근 적산 전문가 1인이 제품 속도를 결정함**  
   확률: **높음**.  
   죽는 경로: 룰 승인, GT adjudication, 고객 미팅, 파일럿 품질 보증, 예외 케이스 해석이 한 사람에게 몰립니다. 그 사람이 바쁘거나 이탈하면 룰팩과 평가가 멈춥니다.  
   예방: 최소 2인 체계 또는 외부 자문위원 풀, 룰 변경 SOP, adjudication playbook, bus factor 지표가 필요합니다.  
   계획 수정 필요: **예.** §10에 “상근 1+”만으로는 부족합니다.

5. **검토 UI가 CAD 뷰어 개발 수렁으로 변함**  
   확률: **중간~높음**.  
   죽는 경로: 사용자가 레이어 제어, 치수 수정, 블록 표시, 원본 렌더 fidelity, PDF 비교, 엑셀 연계, 이슈 협업을 계속 요구하면서 제품이 takeoff 엔진이 아니라 반쪽 CAD/Bluebeam 대체재가 됩니다.  
   예방: 2a UI 범위를 “하이라이트, 승인/반려, 경계 보정, 근거 export” 네 가지로 제한하고, 일반 CAD 편집·도면 관리·협업 기능은 금지 목록으로 둬야 합니다.  
   계획 수정 필요: **예.** §6에 “하지 않는 UI 기능”이 필요합니다.

**결론**

수정 불요가 아닙니다. 반영 충실성 측면에서는 5개 문구 보정이 필요하고, 프리모템 측면에서는 별도 섹션으로 **상업 게이트/채택 게이트/경쟁 해자/재무 게이트/키맨 리스크/검토 UI 범위 제한**을 추가해야 합니다.
