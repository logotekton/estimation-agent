## 실행 스파인 (한 페이지 — 팀의 다음 행동)

> 이하 본문은 리스크·게이트의 상세 정의다. 실행 순서는 이 페이지가 정본.

**T0 시작 조건**: 아래 Day-0 자산 체크리스트가 충족된 날을 0A의 시계 시작으로 기록한다. 달력상 프로젝트 시작일과 혼동하지 않는다.
- 합법적으로 평가 가능한 실무 DWG/PDF 5건 이상(서로 다른 작성 도구·사무소, 폰트/XREF 포함)과 담당자 지정
- CAD 파싱 담당·적산 판정 담당 각 1명 이상 가용, 파일럿 후보 인터뷰 3건 일정 확정
- 공개·합성 데이터 준비와 NDA 스파이크 샘플을 구분하며, §9의 0A 반입 규정 통과 전 NDA 원본 사용 금지. 제품/공유 환경 반입은 별도 파일럿 실데이터 게이트가 차단

**T0부터 2주 (0A)**: F=5~10 DWG/PDF·P≥3 독립 프로젝트 세트 파싱 smoke(파서 경로 결정) / 뷰어 경로 선택(§6 결합 매트릭스) / 엑셀 산출물 샘플 1종(§12) / 파일럿 후보 인터뷰 3건(§2 구매 경제).
**0B 착수 조건 (T0+2주 직후)**: 임계치 역산 메모 / sampling matrix / 잠금된 파서 게이트 테스트셋 / 2a 가정 배포 envelope ADR을 승인·동결한다. 0A 마감과 같은 날 모두 완성하도록 강제하지 않되, 이 네 산출물 없이는 0B 평가를 시작하지 않는다.
**T0부터 누적 4~6주 (0B)**: F=10~20·P≥5 smoke 게이트 정량 리포트(§11 수치 기준) / 부재 스키마 v0(§4-1) / 라멘조 최소 파이프라인 스켈레톤. 스파이크 산출물은 제품 코드가 아니라 **버리는 검증 하네스 + 보고서**.
**2a 개발 착수 조건**: smoke 게이트 통과 + 파일럿 후보 확보 + 전임 CAD 파싱 엔지니어 1명 이상 온보딩 + 자본/번레이트 sanity check.
**2a 상업 단계 구분**: 디자인파트너/무상 검증은 0B 통과 후 가능 → 최초 유료 파일럿은 full F=50/P≥10·설계사≥5, 지원 배포형태, 일반 계약 검토 통과 후(온프렘·배포형이면 GPL/배포 법무 추가) → 반복 판매/팀 확장은 3건 중 1건 이상 유료 전환과 gross margin 검증 후.

### 게이트 분류 — 무엇을 차단하는 게이트인가

모든 게이트를 "착수 전 관문"으로 두면 결정 마비가 온다. 게이트는 차단 대상별로 6종:

| 분류 | 게이트 | 차단하는 것 | 오너 |
|---|---|---|---|
| **착수 차단** | 0A/0B smoke(DWG·PDF·뷰어) + 파일럿 후보 + 전임 인력 + 18개월 자본 대략 확인 | 2a 개발 착수 | 제품·기술 리드 |
| **데이터 반입 차단** | 0A NDA 반입 규정 / 파일럿 실데이터 보안 게이트 | NDA 스파이크 원본 사용 / 제품·공유 환경의 고객 원본 반입 | 보안 책임자 |
| **최초 유료 파일럿 차단** | full F=50/P≥10·설계사≥5 / 지원 배포형태 / 일반 계약 검토 / 온프렘·배포형인 경우 GPL 법무 | DWG 의존 유료 파일럿·대외 성능 약속·온프렘 계약 | 제품 리드·법무 |
| **반복 판매/팀 확장 차단** | 상업 게이트(3건 중 1건 이상 유료 전환 + 단위경제) | 추가 채용·세그먼트 확대·반복 판매 | 사업 책임자 |
| **주장 차단** | 검정력/비열등성 게이트(§0 평가 통계 설계) | "비열등성 입증" 등 대외 표현 — 개발·판매는 막지 않음 | 평가 책임자 |
| **전략 리뷰** | 해자 검증 게이트(§2) | 없음 — 파일럿 종료 후 방향 판단 입력 | 대표·제품 리드 |

## 0. 목표와 성공지표

**목표**: 도면 유래 공종(골조·마감·창호)의 물량을 검증 가능한 근거와 함께 산출하고, 도면 밖 공종(토공·흙막이·가설)은 파라미터 개산 모듈로 커버하여, 견적 검토 완료까지의 총 소요시간을 수작업 기준선 대비 **50% 이상 단축**한다.

### 성공지표
| 지표 | 정의 | 비고 |
|---|---|---|
| 물량 오차 | GT 매칭 항목의 오차 분포. **판정 단위는 공종 라인/부재 그룹 풀(pool) 수준** (GT 1건 = 수백 라인 표본). 총량 % 단독 지표 금지(누락·과다 상쇄 은폐) | GT 10건+는 **최소 축적 기준일 뿐**, 프로젝트 단위 통과 판정은 검정력 게이트(아래 "평가 통계 설계") 충족 후 |
| 항목 재현율/정밀도 | 누락 항목·유령 항목 검출 | 견적 사고의 주범은 물량 오차가 아니라 항목 누락 |
| 검토 완료 시간 | "검토 완료" = 단가가 있으면 영향액 상위, 단가가 없으면 공종 위험 tier 상위+수량 이상치 전건, 그리고 [가정]·[불일치] 플래그 전건 확인 완료. 항목별 확인 행위는 타임스탬프와 함께 기록(§9 감사 증적) | 2a 범위의 목표 단축률 50%. human active와 시스템 귀책 경과를 함께 측정 |
| **검토 완료 후 발견 오류율 (escaped defects)** | 파일럿 사무소의 사후 정산·감수에서 발견된 오류율. **단축률은 이 지표가 기준 이하일 때만 유효** — 플래그를 생성하는 것은 시스템 자신이므로, 페어 지표 없이는 "플래그 억제 → 검토 단축 달성"이라는 조작 유인이 내장됨. **기준은 절대치(0)가 아니라 "수작업 대비 비열등(non-inferiority)"** — 수작업에도 사후 오류는 존재하므로. 수작업 기준선 오류율은 기존 GT 웨이브의 2인 독립 산출 상호 대조에서 추가 비용을 최소화해 1차 추정 | 단축률의 페어 지표(필수). 통계 설계는 아래 "평가 통계 설계" 참조 |
| 미검토 항목 사후 오류율 | 등급화로 인한 하위 항목 미검토가 품질 저하를 은폐하는지 감시 | |
| 반자동 개입 1회당 UX 소요시간 | 기준층 레버리지 논리의 성립 조건(개입이 10분이면 논리 붕괴) | 뷰어 스파이크 산출물 |
| **층·동·타입당 개입 수** (벽식) | 개입 1회 시간이 짧아도 개입 총량이 크면 레버리지 붕괴 — 벽식 2b 성패 지표 | Codex 교차검증 반영 |
| **carry-forward 재검증 시간·오류율** (리비전) | 이월된 확정 사항의 재검증 소요와, 미검토 이월이 만드는 오류율 | Codex 교차검증 반영 |

### 평가 통계 설계 (Codex 교차검증 반영 — 주장 가능 범위의 사전 고정)
- **분석 단위**: 공종 라인/부재 그룹 풀. 단 같은 프로젝트·도면·검토자에 묶인 **군집 자료**이므로 독립 표본 취급 금지 — 프로젝트를 클러스터로 하는 cluster-robust CI 사용.
- **비열등성 마진 δ**: gold GT 2인 독립 산출의 상호 대조 편차에서 도출하여 **사전 지정**. paired binary 구조에는 McNemar류/GEE 적용.
- **검정력 게이트**: 표본수가 검정력 산정을 통과하기 전에는 프로젝트 단위 비열등성 판정을 **선언 불가** (참고: 프로젝트 10건 무결함이어도 one-sided 95% 상한 ≈ 26%).
- **paired 프로토콜**: gold GT 웨이브(1차 3~5건)는 기존 2인 독립 산출에 시스템 보조 산출을 제3 암으로 추가하여 전건 paired. 파일럿 실 프로젝트는 영향액 상위 + 무작위 혼합의 **층화 샘플링 paired**(전수 수작업 병행은 비용상 배제).
- **masked adjudication**: escaped-defect 판정자는 산출 주체(시스템/수작업)와 시스템 플래그·출처를 보지 못하는 표준 양식으로 판정.
- **주장 한계**: escaped-defect 장기 관측이 성숙하기 전에는 "adjudicated sampled defect 기준의 내부 게이트 통과"까지만 주장하고, 시장·품질 비열등성 확정 표현은 금지.
- **운영 규모 (라운드 7 비용 대칭성 반영)**: 이 설계는 **주장 차단 게이트**다 — 개발·판매를 막지 않는다. 3-arm paired·masked adjudication은 gold GT 웨이브와 층화 샘플 항목에만 적용(전 파일럿 운영 프로세스화 금지). 검정력·cluster CI는 제품 기능이 아니라 **분석 노트북/평가 프로토콜 문서**로 시작.

**시간 단축 주장 프로토콜**:
- 2a의 50% 단축 주장은 **전체 견적**이 아니라 `라멘조 골조(콘크리트·거푸집 판정 + 철근 초안) 검토 완료` 범위로 한정한다. 전체 견적 주장은 마감·창호 등 해당 범위가 실제 평가에 포함된 뒤 단계적으로 승격한다.
- gold GT 3-arm에서는 동일 프로젝트·동일 검토 범위의 수작업 대 시스템 보조 시간을 paired 비교한다. 실파일럿은 동일 사무소 전후 비교를 기본으로 하되 검토자 숙련도, 도면 장수, BOQ 라인/부재 풀 수, 예외·개입 수와 학습 구간을 분리 기록한다. 기존 층화 defect audit 표본에는 시간 기록을 얹어 역사효과를 점검한다.
- 사전등록 주장 지표는 `human active minutes + 시스템 귀책 경과시간(처리·큐·실패/재시도·시스템이 유발한 재업로드)`이다. 사용자측 유휴는 시스템·수작업 양쪽에서 대칭 제외하되 별도 열로 공개한다. `100 BOQ 라인/부재 풀당 시간`은 복잡도 진단 보조 지표다.
- 첫 유료 파일럿 전에 프로젝트 세트 크기별 처리시간 P50/P95, 최초 성공률·재시도 후 성공률, partial-output 정책, 고객 허용 turnaround SLO를 계약에 고정한다. 0단계에서는 파일별 처리시간·성공/실패·사유 코드만 하네스 로그에 남긴다.
- 표본·검정력이 부족하면 "관측 파일럿에서 X% 단축"으로만 표현하며 일반화된 50% 주장을 금지한다. escaped-defect 비열등성 조건과 검토 완료 정의를 동시에 충족해야 유효하다.

기준선 확보: GT 2인 독립 산출에 시간 기록 병행(기존 GT 웨이브에 얹어 추가 비용 최소화 — 단 3-arm paired·masked adjudication 운영비는 별도 발생). GT 산출은 감사용 고품질 산출이라 실무보다 느림 → **파일럿 사무소의 실무 산출 시간 기록으로 기준선 보정**.

> **주의(지연 관측)**: escaped-defect은 사후 정산·감수(검토 완료 후 수개월 뒤)에서 관측되는 지연 지표다. 따라서 파일럿 기간 중의 "단축률 50% 달성" 주장은 오류율 데이터가 성숙할 때까지 **잠정(provisional)** 으로 표기한다 — 내부 보고·투자 커뮤니케이션에서 지표가 조기 확정되는 것을 방지.

후속 성숙 데이터에서 비열등성에 실패하면 잠정 주장을 즉시 철회하고 원인분석·수정·새 버전 재평가 전까지 같은 주장을 재사용하지 않는다.

### 허용오차 (이원화)
| 공종 | 1차 목표 | 성숙 목표 |
|---|---|---|
| 콘크리트 | ±5% | ±3% |
| 거푸집 | ±7% | ±5% |
| 철근 | **2a에서는 허용오차 판정 제외** — "정미량 초안 + 고위험 플래그" 산출물로 한정 (배근상세·이음 위치·후크·커플러·가공손실 미반영 상태의 ±10% 목표는 과감하다는 Codex 지적 수용). 2b 이후 ±10% 판정 승격 | ±7% |
| 실별 마감 | ±10% | ±10% |

- GT 1차 웨이브(3~5건) 중 **최소 3건, 가능하면 전건**을 2인 독립 산출로 inter-annotator 편차를 측정 (n=2는 δ 도출 근거로 빈약). 비용 부담 시 공종/부재 풀 층화 샘플링으로 2인 adjudication 범위 확대. 시스템 목표는 인간 편차보다 커야 함(인간 편차 미만 목표는 정의상 측정 불가).
- **GT 해석 분산 통제**: 두 산출자는 답안을 공유하지 않되 동일한 annotation rubric(포함·공제·단위·경계·모호성 코드)을 사용한다. 본 평가 전 소형 calibration 세트 1회로 rubric 이해를 맞추고, adjudication 시 ambiguity code를 기록한다. 어떤 분산을 δ에 포함·제외할지 사전등록하며 상설 분산 연구는 만들지 않는다.
- **GT 등급 분리 (오염 차단)**: 독립 2인 산출 = **gold**, 파일럿 "검토 완료 BOQ" 사후 축적분 = **silver**. silver는 회귀 평가·오류 발굴에만 사용하고 **δ 도출·비열등성 판정에는 사용 금지** (시스템 산출물이 GT를 오염시키는 순환 차단). 등급 라벨을 GT 스키마에 명기.

## 1. 핵심 아키텍처 결정

**도면 파싱 → 경량 시맨틱 모델(3D 지오메트리 재구성 없는 부재 단위 구조화 데이터) → 룰 기반 물량산출.**

완전 자동 2D→3D BIM 재구성은 배제한다:
1. 연구 단계 난제이며, 도면 해석 오차 위에 모델링 오차가 누적되어 물량 오차의 원인 추적이 불가능해진다.
2. 물량 산출에 필요한 것은 3D 형상이 아니라 부재 속성(유형·규격·길이/면적·높이·공제)이다.

단순 파싱만으로도 부족하다: 물량은 부재 단위로 집계되고 공제·층고·마감 사양이 붙어야 하므로, 파싱 결과를 부재 객체(요소+속성+산출근거)로 승격해야 한다 — 사실상 "지오메트리 없는 BIM".

원칙:
1. **표(일람표·마감표·일반주기·층고표)가 도면 기하보다 정보량이 많다** → 표 구조화 우선
2. **수직 치원(층고·벽높이)은 층고표·단면도에서 파라미터로 취득** — 모델링 없이 3D 물량이 나오는 이유
3. **완전 자동이 아닌 "근거 달린 초안 + 사람 검증"** — 검토 UI가 제품의 본체
4. 누락 정보는 가정 엔진으로 채우되 가정 목록을 견적서에 명시
5. 결정론 파서 우선, VLM은 국소 사용

## 2. 타깃 고객과 사업 가설 (파일럿에서 검증)

**1차 고객(작업 가설): 중소·중견 시공사 견적팀.**
**용도 정의(중요)**: 한국 공공 입찰의 다수는 발주처가 물량내역서를 제공하는 **내역입찰**이라 시공사가 물량을 뽑지 않는다. 물량산출 수요가 실재하는 용도는:
- (a) **민간공사 견적** — 도면만 주고 견적을 요청하는 관행
- (b) **수주 후 실행예산·실행내역 작성**
- (c) **발주 내역 검증** — 제공된 내역의 누락·과소 물량 확인(디스크레펀시 리포트가 정확히 이 기능)

과금 가설: 프로젝트 건당(외주 적산비 대비 할인 포지션). 파일럿 계약에 유료 전환 가격·전환 트리거를 사전 합의로 명기.

**2차 세그먼트**: CM·발주처의 내역 검증 니즈 — 디스크레펀시 리포트가 **잠재 앵커**인 시장 (단독 상품화에는 내역서 매칭 모듈이 선행 필요 — 아래 참조. 반자동 검증 워크플로우로 시작).

**구매 경제 검증 (Codex 교차검증 반영)**: 구매 이유는 "물량 오류 발견" 자체가 아니라 입찰 리스크 회피·클레임/설계변경 근거·CM 감수비 절감 같은 **경제 사건**이다. 시공사 견적팀·CM·발주처는 구매 예산·책임·도입 장벽이 다르므로, 세그먼트별 구매 경제(ROI·법적 사용 가능성) 인터뷰를 병렬 트랙에 포함한다(§11). **용도 c의 숨은 전제**: 단독 상품이 되려면 발주 내역서(엑셀/HWP) 파싱 + 시스템 BOQ와의 라인 매칭(품명·규격 텍스트 매칭) 모듈이 필요 — 파일럿에서는 검토자가 내역서를 옆에 놓고 디스크레펀시 리포트와 수동 대조하는 반자동으로 시작하고, 모듈 자체는 명시적 후순위(§11). 단 **용도 c를 단독 상품으로 판매하기 전에는 이 모듈이 후순위 목록에서 승격되어야 한다**.

**인터뷰 편향 통제**: 구매 의향은 풀비전 설명이 아니라 2a에서 실제 제공할 엑셀 mock과 범위표(콘크리트·거푸집 판정, 철근은 초안+고위험 플래그)를 보여준 뒤 묻는다. `현재 제공`, `수동 보조`, `로드맵`을 화면과 질문지에서 분리하고, 구두 호감이 아니라 데이터 제공·디자인파트너 참여·가격 포함 LOI 중 하나를 검증 신호로 기록한다.

**적산사무소는 고객이 아니라 파트너**: 검토 시간 단축이 공수 기반 수임료와 충돌(가치 제안 역방향). GT 생산·룰팩 감수의 공급자로 유인 설계(룰 기여 수익 공유 또는 우선 사용권).

**경쟁 구도**: 국내 적산 프로그램·단가 DB 사업자(물량은 사람이 입력)와 해외 AI takeoff(Togal.AI·Kreo — 한국 기준·내역 체계 미지원)의 사이. 차별선 = 한국 수량산출기준 룰팩 + 근거 추적성.

**해자 검증 게이트 (프리모템 반영)**: "한국 룰팩"은 해외 경쟁자가 한국 파트너·로컬 룰팩을 붙이면 기능으로 흡수될 수 있는 차별선이다 — 해자로 단정하지 않고 파일럿에서 검증한다. 방어 자산은 룰팩 자체가 아니라 **① 내역 라인 매칭 데이터·발주처별 precedence·검증 로그·고객별 오버라이드 이력에 대한 독점적 학습/계약 권리, ② 국내 적산 프로그램 사업자와의 제휴/화이트라벨 옵션**. 파일럿 종료 시 "축적 데이터가 정확도를 측정 가능하게 개선했는가(플라이휠 실효성)"를 게이트 지표로 판정.

고객 데이터·파생 로그는 파일럿 계약에 대상·목적·보존기간·철회/삭제를 명시하고 opt-in을 받은 범위만 위 ①의 방어 자산으로 계산한다. 권리 조항이 없으면 정확도 개선에 사용하지 않으며 해자 자산으로도 산입하지 않는다.

**리스크**: 시공사 세그먼트는 DWG 재출력 폴백 불가 세그먼트(원도면 재출력 채널·시간 없음)와 겹침 → DWG 변환 충실도가 **사업 가설의 성립 조건**. 스파이크 실패 시 분기(ODA 전환 비용 수용 / 세그먼트 재검토)를 §11 의사결정에 포함.

- **도면 세트 매니페스트**: 입력 단위는 단일 도면이 아니라 세트(수십~수백 장). 프로젝트/issue package ID·목적(입찰/실시/변경), 파일 hash, 시트별 sheet number·분류·revision/date·상태(active/superseded/duplicate)·XREF resolve 상태, 층↔시트 매핑을 기록한다. 동일 sheet number에 active revision이 둘 이상이면 BOQ 생성을 차단하고 권한자가 선택한다. 목적 혼재·폐기본·XREF 미해결은 디스크레펀시 리포트로 보낸다. 표제란 자동 추출이 안 되면 반입 시 수동 확인한다.
- **리비전 차분**: 변경도면 도착 시 재산출 + 차분 리포트. 사람이 확정한 사항(벽 경계, 레이어 매핑)의 이월(carry-forward) 정책을 스키마에 포함 — 시공사 입찰·민간 견적에서 리비전은 일상. **이월은 절대좌표 기반이면 리비전 간 원점 이동·시트 재배치에서 깨짐** → 그리드 교차점·주요 축선·블록/태그 기준 상대좌표 + affine transform의 **기하 앵커링 전략**을 스키마 v0에 포함 (Codex 교차검증 반영).
- **도면 품질 등급 판정기** 최전단 배치: 자동 / 반자동(레이어 매핑·경계 확정 지원) / 불가 즉시 판정.
- **스케일·단위 검증**: 기입 치수 vs 좌표 실측 대조. **자동 정정 금지** — CAD 치수 오버라이드가 존재하므로 어느 쪽이 참인지 기계 판정 불가, 디스크레펀시 리포트로 전달. 채택 우선순위(기입 치수 우선 관행)는 룰팩에 정의.

## 4. 파이프라인

**파서 교체 경계**: 제품 파이프라인은 LibreDWG/ODA/기타 변환기의 원시 객체를 직접 소비하지 않고, 버전이 붙은 canonical ingest IR만 소비한다. 각 변환기는 `parse → IR + diagnostics + unsupported-entity manifest` 어댑터 계약을 구현한다. 0A의 동일 golden fixture를 모든 후보 어댑터에 적용해, full F=50/P≥10에서 경로가 바뀌어도 시맨틱 모델·룰 엔진·UI를 다시 쓰지 않게 한다.

```
입력 → [세트 매니페스트 → 품질 판정 → 스케일 검증]
 ① 기하 추출 (벡터, 결정론 파서)
 ② 시맨틱 추출
    - 텍스트 엔티티: 결정론 추출 / VLM은 표 구조 해석에만 국소 사용
    - 필수 구조화 대상: 부재 일람표, 마감표, 창호 일람표, 구조 일반주기, 층고표
    - 스키마·행/열 합계·원문 좌표 링크·결정론 텍스트 추출 대조를 우선. 필요 시 이중 모델 **불일치만** 플래그 트리거로 사용하며, 모델 간 합치는 정확성·게이트 통과·confidence의 근거로 금지
 ③ 경량 시맨틱 모델 + 교차검증
    - 평면 부재 카운트 ↔ 일람표 대조, 규격 분포 이상치 탐지
    - 층고 미검출 → 해당 수직 부재 물량 [가정] 플래그 강등
    - 디스크레펀시 리포트 (1급 출력물, §7 운영 정책)
 ④ 룰 엔진 (룰팩 구조 — 레이어만이 아니라 거버넌스까지, Codex 교차검증 반영)
    - 정본(source of truth) = 발주처 기준(조달청·LH·표준품셈)
    - 레이어 precedence 명시: 정본 → 프로젝트(특기시방·물량산출 유의서) → 사무소 관행.
      하위 레이어는 상위가 침묵한 곳만 기본값으로 채운다. 명시 규정과 충돌하면 자동 적용 금지
    - 충돌 예외는 승인권자·사유·유효 범위를 가진 **프로젝트 스코프 예외 레코드**로만 적용하고 BOQ 라인에 표시. 한 프로젝트의 예외를 전역 룰팩 변이로 저장 금지
    - 승인된 예외가 없는 미해소 충돌은 자동 침묵 해소하지 않고 디스크레펀시 리포트로 노출
    - 룰 골든 테스트 케이스 / 변경 이력 / 승인권자(상근 적산 전문가) 명시
      (초기 규모: 핵심 룰 5~10개 스냅샷 테스트로 시작, 룰팩 전체 회귀 CI는 오류 사례 축적 후 확장 — 라운드 7)
    - 버전·발주처·사무소별 오버라이드 / BOQ 라인별 적용 룰 ID + 기준 조문 링크
    - 철근: KDS 14 20 52 이음·정착 기본값 + 일반주기 오버라이드, "정미량/반영량" 2라인 출력
      (단 2a에서는 정미량 초안 + 고위험 플래그만 — §0 허용오차 참조)
 ⑤ BOQ 초안: 이산 출처 플래그 [직접추출|추론|가정|불일치발견]
    (수치 신뢰도 점수는 캘리브레이션 데이터 축적 후에만 — 미캘리브레이션 점수는 검토 스킵을 유도해 유해)
 ⑥ 검토 UI (제품의 본체, §6)
```

### 4-1. 중간 표현 스키마 (2a 착수 조건)

**부재 모델 스키마 v0** — 3계층 + 역추적 그래프:
1. **부재 인스턴스**: {ID, 기하 참조(시트·좌표 + **기하 앵커**: 그리드 교차점/축선 기준 상대좌표 — 리비전 carry-forward 성립 조건), 시맨틱 속성, 출처 플래그, 층 귀속}
2. **물량 산식 트리**: 부재 → 산식(치수×층고−공제) → 적용 룰 ID
3. **BOQ 라인**: 공종분류 매핑 + 역추적(라인→산식→부재→도면 위치)

**BOQ 산출 manifest**: 입력 세트 매니페스트 hash, parser 버전, rule baseline(발주처·문서명·판본·사용자 지정 기준일; 기본값 프로젝트 생성일), 프롬프트/모델 버전, 프로젝트 예외 레코드 참조를 기록한다. 룰 baseline 업그레이드는 기존 차분 리포트 메커니즘으로 영향 diff를 보여주고 승인 후에만 적용한다.

"원클릭 수정의 연관 항목 전파", 룰 조문 링크, 검토 완료 BOQ의 GT 환류, 리비전 carry-forward가 전부 이 스키마 위에서만 성립한다. 팀 병행 개발의 전제.

### 4-2. 골조 산출 전략 — 구조형식별 스코프

| 구조형식 | 시장 | 전략 |
|---|---|---|
| 라멘조 (기둥-보) | 오피스·상가·공장 | **2a단계.** 그리드 교차점 + 부재 태그(C1/G1) 카운팅. 태그 대표기입 관행("이하 동일") 대응: 그리드 위상 기반 미태그 부재 보간 로직 필수 |
| 벽식 (전단벽+슬래브) | 아파트·오피스텔 | **2b단계.** 태그 카운팅 불성립 인정 → 반자동 벽 확정 + **구간별 전개(균일 ×N 복제 금지)**: 지하층(외벽 두께 상이) / 필로티·전이층(전이보·전이슬래브 — 물량 밀도 상이, **누락 위험 최대 → 별도 확정 필수**) / 기준층 구간(일람표 층구간별 벽두께 감소 반영) / 최상층·옥탑. 성립 근거: 구조평면은 건축평면보다 깨끗(마감·심볼 없음, 벽 태그 존재) + 기준층 반복 레버리지(개입 1회당 물량 커버리지 최대) |
| 슬래브·기초 | 공통 | 카운팅이 아닌 면적 문제로 별도 취급: 그리드 스팬 근사 + 개구부(계단·EV) 공제는 반자동 경계 확정. **지하주차장 무량판 드롭패널은 가정이 아닌 태그 기반 산출** (해당 구조형식의 체계적 구성요소 + 물량 절대량 큼 + 태그·치수 명시 관례) |

- 드롭 슬래브·헌치·파라펫: 표준 가정 + [가정] 플래그(콘크리트 ±5% 내 흡수 가능), 상세 반영은 후속.

## 5. 도면 밖 공종 — 파라미터 개산 모듈

토공·흙막이·가설은 도면만으로 산출 불가함을 인정하고 파라미터 기반으로 커버: 사용자 입력(굴착깊이, 흙막이 공법, 부지 조건) + 용도별 표준 가정 → 파라메트릭 물량.

**BOQ 2부 구성 강제 분리**: 도면 유래부(허용오차 관리 대상) / 파라미터 개산부(**min~max 범위 출력** — 정밀도 착시 차단). 개산부 오류의 불신이 도면 유래부로 전염되는 것을 구조적으로 방지.

## 6. 검토 UI (뷰어 스파이크 대상)

기능: 항목↔도면 위치 하이라이트(기하 인덱싱), 원클릭 수정 + 연관 항목 전파, 반자동 경계 확정(스냅·폴리곤 편집), 레이어 매핑 지정, 미검토 출력물 워터마크(§9 연동).

**하지 않는 UI 기능 — 금지 목록 (프리모템 반영: CAD 뷰어 수렁 차단)**: 2a UI 범위는 **하이라이트 / 승인·반려 / 경계 보정 / 근거 export** 4종으로 제한. 일반 CAD 편집(치수 수정·블록 편집·레이어 제어), 도면 관리(버전·배포), 협업(코멘트·이슈 트래킹), 원본 렌더 fidelity 개선 요구는 **명시적 금지 목록** — 사용자 요구가 누적되어 제품이 takeoff 엔진이 아닌 반쪽 CAD/Bluebeam 대체재로 변질되는 경로를 차단. 금지 목록 해제는 로드맵 단계 전환 시에만 재심.

**뷰어 의사결정 — DWG 변환 스파이크와 결합된 단일 매트릭스** (독립 결정이 아님: LibreDWG 실패로 ODA 전환 시 뷰어 바이의 경제성이 달라짐):
- §9의 2a 가정 배포 envelope ADR을 이 매트릭스의 입력으로 사용한다.
- 후보 1 (바이): 상용 뷰어 SDK — 단, APS(Forge)류 클라우드 전용은 온프레미스 요구와 충돌, ODA 계열은 ODA 비용 트리거와 결합
- 후보 2 (빌드): 원본 CAD 충실도 렌더러 자체 개발
- **후보 3 (빌드, 유력)**: **중간 표현(§4-1)을 자체 캔버스/WebGL로 렌더 + 원본은 래스터 스냅샷 배경**. 검토자가 봐야 하는 것은 근거 하이라이트 + 부재 폴리곤 편집이지 원본 DWG 완전 재현이 아니며, 이 경로는 DWG·벡터PDF·스캔본을 단일 렌더러로 통합한다. **단 순환 의존 주의: "래스터 스냅샷 배경" 자체가 DWG→래스터 렌더러를 요구하므로 후보 3의 성립은 DWG 스파이크의 렌더 충실도 결과에 의존** — 결합 매트릭스에 명시. 렌더 불충분 시 대안: ODA 렌더 / headless CAD / 고객 제공 PDF / 사전 플롯 워크플로우
- 래스터 배경↔벡터 오버레이의 **좌표 정합 오차 허용치를 스파이크에서 수치로 정의**
- 평가 축: 라이선스 비용, 온프레미스 호환성, 폴리곤 편집 확장성, **반자동 개입 1회당 UX 소요시간**(스파이크에서 측정)
- 결론은 스파이크가 내리되, **T0+2주 내 결론** — 2a UI 착수를 블로킹하지 않는 것이 일정의 선행 조건

## 7. 디스크레펀시 리포트 운영 정책

- 도면 간 불일치(평면↔일람표↔치수)는 오류가 아니라 **1급 출력물** — 내역 검증 세그먼트(§2 용도 c)의 **잠재 앵커** (단독 상품화에는 내역서 매칭 모듈 선행 필요, 반자동 검증 워크플로우로 시작 — §2).
- **물량 영향액 기준 등급화·정렬**, 상위 N건 우선 노출 (전건 나열 시 alert fatigue로 성공지표인 검토 시간이 오히려 악화). 고객 BOQ 단가 import를 선택 입력으로 받고 단가 매칭은 `[직접매칭|유사매칭|기본단가|단가없음]`으로 표시한다. 단가 출처·판본/기준일·수동 override를 기록하며, 단가가 없으면 금액 순위를 만들지 않고 공종 위험 tier+수량 이상치로 강등한다. 위험 tier 정의·변경은 룰팩 승인권자 소관이며 변경 이력에 남긴다.
- 무시 패턴 학습은 **숨김이 아닌 접힘(collapsed)**: 강등 유형도 영향액 임계치 초과 시 재부상 + 강등 이력 감사 로그 (학습된 침묵이 실제 사고를 삼키는 것 방지).

## 8. 평가 체계

- **GT 웨이브** (순차 병목 방지): 1차 3~5건(그중 **최소 3건, 가능하면 전건** 2인 독립 산출 + 시간 기록)으로 2a 개발 병행 착수 → 파일럿 실 프로젝트의 "검토 완료 BOQ"를 **silver GT**로 축적하는 플라이휠 (gold/silver 등급 분리와 사용 제한은 §0 참조 — silver는 δ 도출·비열등성 판정 사용 금지).
- **paired 평가 설계**: gold GT 웨이브는 2인 독립 산출 + 시스템 보조 산출의 3-arm paired. 파일럿 실 프로젝트는 층화 샘플링 paired + masked adjudication (§0 평가 통계 설계).
- **튜닝 누출 차단**: 초기 gold 중 최소 1프로젝트는 frozen holdout으로 두고 룰·프롬프트 튜닝에 사용하지 않는다(이 1건으로 일반화 주장 금지). 신규 파일럿은 수정 전에 첫 패스 지표를 고정해 rolling out-of-sample 신호로 사용한다. 각 평가 실행은 입력 hash와 parser/rule/prompt/model 버전을 산출 manifest로 남긴다.
- **coverage 병렬 보고**: 0A/0B는 매니페스트의 물량 관련 시트(구조평면·일람표·층고표·마감표)를 분모로 `[자동|부분(경고)|불가]` 비율과 고정 사유 코드를 보고한다. 2a부터는 BOQ 금액 중 `[직접추출|추론|가정|불일치발견]` 출처 분포를 추가한다. coverage·정확도·시간을 하나의 합성 지수로 압축하지 않는다.
- 도면 소싱: 공공 발주 설계도서(입찰 공고 첨부)는 **PDF 중심이라 평가 보조·GT용** — DWG 스파이크용 실무 도면은 NDA 샘플·협력사·파일럿 파트너·공개 입찰 원본 요청 채널로 소싱(§11 0A/0B/full 3단 게이트와 일치).
- 허용오차 회귀 평가 CI화(항목 풀 수준 판정, §0).
- 파일럿 적산사무소 1~2곳 + **발주처 기준 준수를 제3 검증 채널로** (사무소 관행 과적합 방지).

## 9. 데이터·법무·책임

- 고객 도면 비밀유지·저작권: 완전 비식별화를 약속하지 않는다. 메타데이터·불필요 영역 최소화와 가명처리만 수행하며, 모델/룰 개선은 기본 미사용(opt-in), 목적 제한, 프로젝트 계보, 보존기간, 삭제·철회와 파생 데이터 처리를 파일럿 계약에 명시한다.
- **0A 전 NDA 도면 반입 규정**: 암호화 저장, 접근자 한정, 외부 서비스(VLM 포함) 전송 금지, 요청 시 삭제를 1페이지 규정으로 고정한다. 이것은 0A에서의 NDA 원본 사용을 차단하며 공개·합성 데이터 선행 작업은 막지 않는다.
- **파일럿 실데이터 반입 게이트 (가정 배포 envelope ADR 이후)**: 고객 원본을 제품/공유 환경에 넣기 전에 1페이지 체크리스트 수준의 데이터 흐름도·최소 위협모델을 작성하고, 업로드 파서를 네트워크·파일시스템이 제한된 샌드박스에서 실행한다. 파일 크기·압축 해제·CPU/메모리/시간 상한, 악성코드 검사, 파서 크래시 격리, 지원하지 않는 엔티티의 명시적 실패를 검증한다.
- **접근·격리**: 전송/저장 암호화, 프로젝트/테넌트별 논리 격리, 최소권한 RBAC, 운영자 접근 승인·감사로그, 비밀값 분리, 복구 테스트를 2a 기본선으로 둔다. 테넌트 간 파일·인덱스·로그 조회를 막는 부정 테스트가 실데이터 반입 게이트의 필수 산출물이다.
- **보존·삭제**: 계약별 원본/중간산출물/로그 보존기간, 사용자 삭제 SLA, 백업에서의 만료 시점, 계약 종료 export·파기 증적을 정한다. 모델 개선은 기본 거부(opt-in)이며 동의 데이터도 원계약·프로젝트·버전 계보를 유지한다.
- **외부 VLM 통제**: 고객 파일럿뿐 아니라 GT·개발용 NDA 도면에도 동일 적용한다. 전송 영역을 표·주기 crop으로 최소화하고, 공급자별 학습 사용 여부·보존기간·처리 리전·하위처리자·DPA를 기록한다. 고객/계약이 외부 전송을 금지하면 결정론 파서 또는 승인된 로컬 모델로 강등하며 조용히 우회하지 않는다.
- **사고대응**: 도면 유출·교차테넌트 노출·악성파일·잘못된 삭제를 최소 시나리오로 한 탐지·격리·통지·증적보존 runbook과 책임자를 최초 디자인파트너 반입 전에 지정한다.
- **가정 배포 envelope ADR (0B 착수 조건)**: 인터뷰에서 보안·망분리·외부 VLM 허용 여부를 확인해 2a 작업 가정을 `SaaS`, `고객 전용 private cloud`, `offline on-prem` 중 하나 또는 제한 조합으로 명시한다. 인터뷰 3건으로 확정하지 않으며 작성일·오너·재검토 트리거를 둔다. 뷰어 결합 매트릭스는 이 ADR을 입력으로 삼고, 고객 요구·원가가 가정을 깨면 재검토한다.
- 온프레미스 요구 대응: 일반 계약 검토는 모든 최초 유료 파일럿 전에 수행하되, §3의 GPL/배포 사실관계 법무 검토는 온프렘·배포형 계약에 한정한다. 방어적 프로세스 격리는 설계 선택일 뿐 법률 결론으로 표현하지 않는다.
- **산출 오류 책임 구조**: 약관 책임 한계(도구는 보조, 최종 서명은 검토자) + 항목별 확인 타임스탬프를 **안전·감사 증적의 보조 자료**로 기록(법적 효력은 약관·보험과 함께 법무 검토) + 미검토 출력물 워터마크 + 손해배상 보험 검토. 하위 tier만 그룹 승인, 예외 override 사유 필수, 기존 타임스탬프에서 확인 속도 분포를 월 1회 점검한다. [가정] 플래그·min~max 출력을 책임 구조와 연결.
- VLM 비용: 결정론 파서 우선, 표·주기 영역 국소화.

### 재무·상업 게이트 (프리모템 반영)

파일럿 유료 전환 전에 번레이트가 자본을 소진하는 것이 실패 확률 중~높음의 사인. 이 계획은 **팀 4~6인 × (0단계 4~6주 + 2a 5~6개월 + 파일럿 기간) ≈ 18개월 생존 자본**을 전제한다 — 건당 과금은 초기 매출 인식이 늦고 파일럿은 할인/무상일 가능성이 크므로.
- **0단계 종료 전 숫자로 확정할 것**: Day-0 예상 기간·비용 / 필요 자본 총액 / 월 번레이트 / GT·adjudication 비용 상한 / ODA 전환 시 원가 증분 / 목표 프로젝트 단가 / gross margin / 유료 전환 목표 건수.
- **최초 유료 파일럿 게이트**: full F=50/P≥10·설계사≥5, 지원 배포 envelope, 일반 계약 검토, 목표 프로젝트 단가에서의 예상 gross margin을 통과해야 한다. 온프렘·배포형이면 GPL/배포 법무를 추가한다. 무상 디자인파트너 검증과 혼동하지 않는다.
- **반복 판매/팀 확장 상업 게이트 (예시 기준, 계약 전 확정)**: 유료 전환 트리거를 사전 합의하고 완료한 파일럿 3건 중 최소 1건 유료 전환 + 실제 원가 기준 gross margin 하한 충족. 미달 시 추가 채용·세그먼트 확대를 멈추고 과금/범위를 재검토한다.
- 상업 게이트는 기술 게이트와 독립적이다. 기술 통과는 디자인파트너 검증을 허용할 뿐 반복 판매·조직 확장의 충분조건이 아니다.

## 12. 출력 규격

- **한국 내역 체계 매핑 = 1급 과업**: 공종분류(표준품셈 체계), 내역서 엑셀 포맷, 내역 프로그램 연동.
- **엑셀 퍼스트 산출물 (프리모템 반영 — 채택 마찰이 최대 사인)**: 견적팀은 정확도가 좋아도 엑셀/HWP 중심 산출물·마감 임박 일정·내부 결재 포맷·도면 업로드 보안 부담 때문에 새 UI를 떠나지 않는다. 첫 파일럿 산출물을 "웹앱 사용"이 아니라 **"기존 엑셀 양식에 근거 링크가 붙은 검토 리포트"**로 정의 — 검토·경계 확정은 UI에서 하되, 최종 산출물과 결재 흐름은 고객의 기존 양식에 착지시킨다.
- **채택 마찰 KPI**: 엑셀 export/import 왕복 성공률, 기존 내역 프로그램 연동, 보안 문서·온프레미스/로컬 처리 옵션 제공 여부를 채택 지표로 관리. (초기에는 수동 체크리스트로 충분 — instrumentation은 첫 유료 파일럿 이후, 라운드 7)
- IFC는 내부 부재 분류 명명 수준으로만 차용(비용 ~0, 공공 BIM 확대 **추진 계획** 대비 보험 — 국토부 제7차 건설기술진흥 기본계획은 2026년 500억원+, 2028년 300억원+ 신규 공공사업으로 확대 적용을 추진한다고 명시). **분류 체계의 정본은 한국 내역 매핑 측** (IFC 클래스↔한국 공종은 다대다 — 예: IfcCovering 하나가 미장·도장·수장으로 갈라짐).
