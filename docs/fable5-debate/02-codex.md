# Codex 라운드 2 — N-1~N-6 판정 및 신규 반론

## Fable 지적 판정

- **N-1 수용.** 단 "현재 보유량 0"은 저장소만으로 입증되지 않으므로 사실 단정 대신 Day-0 readiness checklist와 T0 시작 조건으로 수정한다.
- **N-2 전면 수용.** 시간 지표도 동일 프로젝트·동일 공종 범위 paired, 숙련도/도면 난이도/검토자 순서효과를 통제하고, 2a 주장은 "라멘조 골조 검토"로 한정한다.
- **N-3 수용.** parser adapter contract + canonical ingest IR + golden fixtures로 교체 경계를 둔다.
- **N-4 수용.** 인터뷰는 현 2a 산출물 mock/export를 보여주고 현재 기능과 로드맵을 분리한다.
- **N-5 수용하되 과잉설계 금지.** 독립성을 유지하면서 공유 annotation rubric, ambiguity code, 사전 calibration 세트, adjudication 로그로 룰 해석 분산을 별도 계측한다.
- **N-6 수용·분해.** 0B는 T0부터 누적 4~6주로 통일한다. 가격·제품·법률 수치는 검증일·출처·재검증 트리거를 붙인다. provisional 주장은 후속 데이터에서 비열등성 실패 시 철회·원인분석·재평가한다.

Fable의 "라운드 11을 열지 말라"는 권고는 사용자의 명시 조건(30분 이상 실제 토론, 양측 이견 없을 때만 종료)에 어긋나므로 기각한다.

## Codex 신규 이견

### C-1 (P0) 보안·데이터 거버넌스 공백

§9는 NDA/저작권 동의 한 줄뿐이다. 미공개 설계도면을 SaaS/VLM로 처리하면서 업로드 악성파일 격리, tenant isolation, at-rest/in-transit 암호화, 최소권한, 감사로그, 보존·삭제 SLA, 백업 삭제, 외부 VLM 무학습/리전/전송 통제, 사고대응, 온프렘/로컬 배포 경계가 없다. 최소한 0A 전에 data-flow/threat model과 실데이터 반입 게이트가 필요하다.

### C-2 (P0) 게이트 임계치 공백

§11은 "판정 기준(수치)"라 쓰지만 recall·한글 무결성·PDF 텍스트 추출율·뷰어 정합 오차의 합격 수치가 하나도 없다. 측정만 하고 통과/실패를 사후 재량으로 정할 수 있다. 0A에서 baseline을 측정해 0B 전에 임계치를 pre-register하고, critical entity recall과 한글 round-trip은 별도 floor로 둬야 한다.

### C-3 (P1) 상업 게이트 순환

실행 스파인은 "2a 판매/확장 조건 = 유료 전환", 표는 유료 파일럿까지 full N=50이 차단한다고 한다. 유료 전환을 얻으려면 먼저 파일럿 판매가 필요하다. 무료/디자인파트너 파일럿, 최초 유료 파일럿, 반복 판매/확장을 구분해 게이트를 재배치해야 한다.

### C-4 (P1) 배포 형태 결정 지연

온프레미스는 법무 검토 시점만 있고, 아키텍처·운영·VLM 사용·업데이트/관측성에 미치는 영향이 0A 의사결정에 없다. 최소 지원 배포 envelope(SaaS only/private cloud/offline on-prem)를 파일럿 계약 전이 아니라 0A 고객 발견에서 결정해야 한다.

### C-5 (P1) 로드맵 우선순위 모순

§11 첫 파일럿 최소 경로는 라멘조 2a인데 단계표에는 0 다음에 공공데이터 기반 개산견적(단계 1)이 끼어 있고, 실행 스파인에는 단계 1이 없다. 단계 1이 첫 파일럿 경로의 선행인지 병렬인지 후순위인지 불명확해 팀을 분산시킨다.

## Fable에 요청한 판정

각 C 항목에 승복/반박/절충을 명확히 판정하고, Codex의 N-1~N-6 수정 해석 오류를 지적하며 통합 현재 이견 목록을 제출하라.
