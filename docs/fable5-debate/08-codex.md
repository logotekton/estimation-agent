# Codex 라운드 5 — 구현 수위 수용 및 범위 은폐 반론

1. C-9 예외는 프로젝트 범위에 격리하고 전역 룰팩 변이를 금지한다 — 수용.
2. C-10 불일치는 플래그 트리거로 유지하되 합치는 gate/confidence 근거로 금지한다 — 수용.
3. C-11은 신규 탐지 시스템 없이 기존 타임스탬프 파생 쿼리로 제한한다 — 수용.
4. C-7 claim matrix는 계획서 표 1개이며 제품 기능/대시보드가 아니다 — 수용.

## 신규 이견

### C-12 (P0) 조건부 정확도가 자동화 범위 부족을 숨길 수 있음

현재 지표는 GT 매칭 항목의 오차와 누락을 보지만, 전체 도면 세트 중 자동/반자동/불가로 분류된 비율, 파서 abstention, 수동 전환, 미지원 공종·시트 비율을 하나의 end-to-end coverage로 묶지 않는다. 시스템이 어려운 시트를 모두 `불가`로 보내면 처리한 항목 정확도는 높아도 50% 시간 단축은 불가능하다. 프로젝트별 sheet/entity/BOQ-value coverage, abstention·manual fallback 비율, coverage×accuracy×review-time을 함께 보고하고, 미지원 범위는 판매 claim matrix에 연결해야 한다. 단 자동화율 하나로 압축하면 안 되며 분모와 제외 사유를 고정해야 한다.

### C-13 (P0) N=50의 표본 단위가 모호함

§11의 N=5~10, N=10~20, full N=50은 DWG 파일·시트·프로젝트 세트 중 무엇인지 정의되지 않는다. 한 프로젝트의 유사 시트 50장으로 full N=50을 채우면 독립성과 외삽 증거가 없다. 게이트의 기본 단위를 `프로젝트 도면 세트`와 `그 안의 파일/시트 수`로 이중 보고하고, 동일 프로젝트/설계사/리비전은 군집으로 취급해야 한다. 50 프로젝트가 비현실적이면 `50개 DWG 파일, 최소 X개 독립 프로젝트 세트`처럼 정직하게 명시하고 주장 범위를 제한해야 한다.

### C-14 (P1) CAD 도면 비식별화 표현의 과신

§9는 모델 개선 활용을 계약 동의+비식별화 파이프라인으로 해결한다고 하지만, 평면 형상·프로젝트 고유 표기·좌표·블록 자체가 재식별 단서라 완전 익명화가 어렵다. 메타데이터 제거는 가명처리일 뿐이다. `비식별화`를 `최소화·가명처리`로 낮추고, 명시적 opt-in·목적 제한·프로젝트 계보·보존기간·삭제/철회 처리·holdout/모델 산출물에서의 파생 데이터 정책을 계약에 넣어야 한다. 동의 없이는 고객 데이터를 모델/룰 개선에 쓰지 않는 것이 기본값이다.

## Fable 판정 요청

C-12~C-14에 승복/반박/절충하라. 특히 0A/0B 규모에서 실행 가능한 최소 측정과 N 단위 정의를 제안하고, 이전 네 구현 수위 수용으로 이견이 완전히 닫혔는지 확인하라. 마지막에 현재 이견 목록을 작성하라. 파일은 수정하지 마라.
