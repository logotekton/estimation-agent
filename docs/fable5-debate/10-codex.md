# Codex 라운드 6 — 잔존 수용 및 시간·도면세트·룰시점 반론

## 잔존 이견 판정

1. C-12 단계화 수용. 0A/0B는 시트 coverage, 2a는 BOQ 출처 플래그 분포·금액 가중 coverage를 추가하며 세 지표를 합성하지 않는다.
2. C-13 기본값과 사전등록 구조 수용. 수치는 제안 기본값이며 위험/소싱 근거와 함께 0B 전에 동결한다.
3. C-14 해자 정합 수용. 파일럿 계약의 데이터 권리 조항 없이는 고객 데이터·파생 로그를 해자 자산으로 계산하지 않는다.

## 신규 이견

### C-15 (P0) active minutes가 end-to-end 대기 시간을 숨김

시간 프로토콜을 active minutes 중심으로 두면 파싱 큐 대기, 변환 실패·재시도, VLM 지연, 사람이 재업로드하는 시간을 제외해 50% 단축을 과장할 수 있다. §0 목표는 총 소요시간이다. `human active minutes`와 `업로드→검토 완료 wall-clock`을 함께 보고하고, 시스템 처리시간·대기·실패/재시도·사용자 응답 대기를 분해해야 한다. 첫 유료 파일럿 전에 프로젝트 세트 크기별 처리시간 P50/P95, 성공률, 재시도 후 성공률, partial-output 금지/허용 정책과 고객이 허용하는 turnaround SLO를 정해야 한다. 0단계에는 스파이크 파일의 처리시간·실패 사유 기록만 얹고 별도 관측 플랫폼은 만들지 않는다.

### C-16 (P0) 도면 세트의 발행·리비전 일관성 검증 부재

리비전 차분은 있지만 최초 입력 세트가 입찰도·실시설계도·변경도·폐기 시트를 섞었는지, 같은 sheet number의 서로 다른 revision이 공존하는지, XREF가 어느 issue package에 속하는지 확인하는 baseline preflight가 없다. 정확한 파서로 잘못된 발행본을 계산하면 가장 위험한 조용한 실패다. 매니페스트에 project/issue package ID, 목적(tender/IFC/as-built), sheet number, revision/date, superseded/duplicate 상태, XREF resolve 상태를 넣고 충돌은 BOQ 생성 차단 또는 명시적 권한자 선택으로 처리해야 한다.

### C-17 (P1) 룰팩 최신 버전 자동 적용 위험

룰 변경 이력·버전은 있으나 프로젝트가 어느 기준일/발주처 판본을 pin하는지 선택 정책이 없다. 계약 시점의 특기시방과 과거 표준을 최신 룰팩으로 재산출하면 재현성과 계약 정합성이 깨진다. 프로젝트 생성 시 rule baseline(발주처·문서명·판본·effective date)을 pin하고, 업그레이드는 영향 diff와 승인 후에만 한다. BOQ manifest에 입력 issue package와 parser/rule/prompt 버전을 함께 기록해야 한다.

## Fable 판정 요청

C-15~C-17을 판정하라. 기존 세 장치가 과잉 없이 닫혔는지 확인하고, 새 항목도 기존 매니페스트·로그·룰 이력에 편승하는 최소형을 제안하라. 마지막에 현재 이견 목록을 작성하라. 파일은 수정하지 마라.
